# Phase 0 — Issue #2 / v1.3 갭 분석 및 단계별 구현 계획

> 이 문서는 최초 분석 시점의 기록이다. 이후 사용자의 액션 성장 축 요청에 따른 진행 결과는 [Phase 1 액션 축 보고](PHASE1-ACTION-AXIS.md)를 참조한다.

## 개발 기준과 이번 작업 범위

- 작업 요청: [GitHub Issue #2](https://github.com/ghkdwo0202-crypto/dead-memory/issues/2).
- 기준 문서: [PR #1의 v1.3](https://github.com/ghkdwo0202-crypto/dead-memory/blob/f6799c658c811df24d282e04d42b61a24de8ba64/docs/MEAT-MARKET-BUILD-SPEC-v1.3.md), PR head `f6799c658c811df24d282e04d42b61a24de8ba64`에서 원문 그대로 읽어 이 저장소의 같은 경로에 보관했다.
- 배포 기준선: `main` 커밋 `5ea7b11` (v0.2, 오프라인 ZIP 제공).
- 작업 폴더에는 이전 요청으로 작성 중이던 v0.3 변경이 남아 있다. 이를 기준선에 합쳐 완료한 것으로 계산하지 않는다. 이번 수행은 분석/문서 정리에 한정하고 프로그램 코드·다운로드 ZIP·워크플로는 새로 변경하지 않았다. PR 병합·커밋·푸시·환경 게시도 하지 않았다.
- Issue의 요구대로 첫 결과는 갭 분석과 계획이다. Phase 1 이후를 한꺼번에 구현하지 않는다.

## 1. 엔진·실행·코드 구조

엔진은 브라우저 Canvas 2D, 언어는 JavaScript ES modules다. Node.js 22 이상을 개발 도구로 사용하며 이번 실행은 24.19.0이다. 외부 런타임 의존성이 없는 구조를 유지한다.

| 파일/구성                             | 현재 책임                                                   | 재사용 방침                                                                            |
| ------------------------------------- | ----------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `src/data.js`                         | 기관·변이·상태·적·런 설정                                   | 데이터 리소스 방식 유지. 정의 검증, 새 카탈로그, 비용/상한 추가                        |
| `src/core.js`                         | Actor, OrganSystem, CombatEvents, Game 및 전투/AI/성장/저장 | 실행기와 이벤트 큐 재사용. 장착 트랜잭션·스탯 집계·상태/이벤트 계약을 작은 단위로 확장 |
| `src/game.js`                         | 키보드 입력, 메뉴·HUD·게임 루프                             | 방향키/Z/X/C/Enter/Esc 유지. 교체/환급·적응·빌드 검사·디버그 메뉴 확장                 |
| `src/render.js`                       | Canvas 외형·전조·효과                                       | 기존 효과 유지, 타깃 콘 디버그와 새 기관 표시 추가                                     |
| `src/navigation.js`, `src/storage.js` | 시야/BFS, 저장 실패 폴백                                    | 유지. 저장 스키마 이전 계층 추가                                                       |
| `tests/combat.test.js`                | 기존 40개 회귀 테스트                                       | 삭제/비활성화하지 않고 버전 호환과 새 계약 테스트를 별도 추가                          |

실행: `npm start`. 검증: `npm test`, `npm run check`, `npm run build:pages`, `npm run build:standalone`. 다운로드 갱신용 `npm run build:download`는 검증 완료 뒤에만 실행한다.

## 2. 기관 9종과 v1.3의 22종

다음은 **같은 콘셉트의 대응**이며 수치/행동까지 v1.3과 일치한다는 뜻은 아니다.

| 부위 | 현재 ID → v1.3 대응                                                | 현재/목표  | 빠진 정의와 실제 효과                                    |
| ---- | ------------------------------------------------------------------ | ---------- | -------------------------------------------------------- |
| 팔   | ARM_SAW → ARM01, ARM_SPINE → ARM02                                 | 2 / 4      | ARM03 골격 분쇄 팔, ARM04 채찍 촉수 팔                   |
| 등   | BACK_TENTACLE → BACK01, BACK_TURRET → BACK02, BACK_BLADES → BACK03 | 3 / 6      | BACK04 독낭, BACK05 번식/소환, BACK06 전기 기관          |
| 심장 | HEART_HUNGER → HEART01, HEART_BLAST → HEART02                      | 2 / 6      | HEART03 응고, HEART04 과충전, HEART05 기생, HEART06 불사 |
| 눈   | EYE_BLOOD → EYE01, EYE_HUNTER → EYE02                              | 2 / 6      | EYE03 포식자, EYE04 전염, EYE05 약점, EYE06 군집         |
| 합계 | 9개 콘셉트 재사용                                                  | **9 / 22** | **13종 추가 필요**                                       |

기존 기관도 조정이 필요하다. 톱날은 현재 매 적중 출혈이며 동일 대상 3회 적중/3타 보너스가 없다. 포식 촉수는 저체력 추가 피해가 있지만 기본 저체력 우선순위가 아니다. 굶주린 심장은 현재 고정 +25%/2초이며 v1.3의 +8%×5/3초가 아니다. 폭발 심장은 5처치/피해 28/반경 160이며 목표는 8처치/30/90이다. 사냥꾼의 눈은 여러 대상을 표시할 수 있고 자동 피해 +30%로, 단일 주 표식/+20%와 다르다. 수치는 초기 튜닝이므로 사양 정합성과 재미 검증을 분리한다.

## 5. ‘피의 도살자’와 8종 대표 빌드 판정

v1.3의 첫 수직 슬라이스는 ARM01 + BACK01 + HEART03 + EYE01, ARM01에 MUT07/MUT12, BACK01에 MUT15다. ARM/BACK/EYE의 유사 구현은 재사용 가능하지만 HEART03이 없고 세 변이의 ID/이벤트 조건/치유·가속 상한이 모두 다르다. 따라서 **현재 상태로 v1.3 피의 도살자를 완료했다고 볼 수 없다.**

나머지 7종 역시 누락 기관·적응과 변이 의미 변경 때문에 사양 그대로 구성할 수 없다. 디버그 편집기에서 각 레시피를 검증하는 테스트가 필요하다. 기존 v0.3의 ‘혈육 수확자’는 이름과 무관하게 해당 사양의 대체 구현으로 간주하지 않는다.

## 6. 실제 검증 결과와 남은 문제

- `main`의 `5ea7b11`에서 테스트에 필요한 파일만 임시 스냅샷으로 읽어 실행: **기존 테스트 40/40 통과**. 작업 중 소스를 덮어쓰지 않았다.
- 작업 트리의 최근 `npm test`: 기존 40개 통과 + 확장 13개 통과/1개 실패, **합계 53 통과/1 실패**. 원래 테스트를 삭제하거나 우회하지 않았다.
- 실패한 확장 테스트를 별도 관찰: 대시 무적 종료 0.36초, 실제 충돌 0.42초. 테스트가 보스 이동을 진행하지 않고 시계를 0.2초로 넘겨, 의도한 회피 구간과 충돌 구간이 어긋난다. 이 결과는 무적 판정 코드 결함의 증거가 아니며, 이후 해당 범위에서 올바른 시간 진행으로 검증해야 한다. 이번 분석에서는 테스트를 고치지 않았다.
- 현 작업 트리 `npm run check`, `npm run build:pages`, `npm run build:standalone`: **통과**. 배포 ZIP은 갱신하지 않았다.
- 이번 작업에서 브라우저 수동/통합 테스트는 다시 실행하지 않았다. 기존 v0.2 키보드 검증을 v1.3 전체 수락 테스트 통과로 해석하지 않는다.

## 7. 단계별 구현 계획

### Phase 0 — 이번 보고

Issue/PR 문서 확보, 엔진/코드/배포 기준선 확인, 기관·변이·핵심 계약 갭과 저장 위험 식별. 이 문서와 원문 보관만 변경한다.

### Phase 1 — 다음 구현 단위: 키보드 전투 정합성

기존 입력/공격/대시를 유지하면서 타깃 우선순위·마지막 방향·활성 프레임 고정·무기별 버퍼/취소를 정렬한다. 적 공격 instance ID와 공격별 실제 성공 회피, 동일 인스턴스 중복 피해 방지를 검증하고 콘 디버그 표시를 제공한다. 방향키+Z/X/C, 홀드, 무마우스 시작/일시정지/재시작을 검사한다. **새 기관·변이 전체나 적응 카탈로그는 이 단계에 추가하지 않는다.** 작업 중 v0.3 확장은 복구 가능한 형태로 보존해 기준선과 분리한 뒤 필요한 코드만 재사용한다. 종료 시 파일/변경/테스트/미해결을 먼저 보고한다.

### Phase 2 — 장착/데이터 계약

버전 있는 BuildState, 명시적 legacy ID 변환, 기관 2변이 제한, 장착 트랜잭션, 환급 토큰/미리보기, 파생 스탯 집계부터 구현한다. ARM01/02·BACK01/02·HEART03·EYE01/02의 7종 범위로 제한한다. 기존 보유 데이터가 다른 효과로 바뀌거나 사라지지 않음을 검사한다.

### Phase 3 — 피의 도살자 하나 완주

출혈, OnDirectHit/OnKill/OnStatusApplied 순서, MUT07/12/15, 적응 1종을 추가한다. 출혈 우선 표적 → 직접 적중 회복 → 자동 마무리 → 전파/가속을 실제 플레이로 검증한다. 치유/스택/쿨다운·킬 귀속·연쇄 한도·보스 예외 테스트를 포함한다. 다른 7개 빌드는 아직 완료 처리하지 않는다.

### Phase 4 이후 — 후속 보고를 거쳐 확장

남은 13기관과 나머지 변이/적응을 기능군별로 나눠 확장하고 8개 레시피/seed 보상/디버그 편집기를 검증한다. 그 후 적/보스·고밀도 성능/튜닝, 마지막에 추적자를 조정한다. 현재 존재하는 적·보스·추적자 코드를 버리거나 다시 만들지 않는다.
