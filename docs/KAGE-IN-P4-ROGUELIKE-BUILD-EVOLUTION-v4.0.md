# KAGE//IN — P4 로그라이크 인술 진화 및 전투 빌드 설계 v4.0

> **Codex implementation contract / design baseline**. P3 문서 `docs/KAGE-IN-P3-SIDEVIEW-AUTO-NINJUTSU-v3.1.md`의 **횡스크롤·즉발 단일 인술·3인 자동 혼합인술**을 유지하면서 P4에서 반복 플레이 성장의 깊이를 추가한다. 기존 P2/P3 코드를 덮어쓰거나 P3 완료 여부를 추정하지 않는다. 모든 수치는 첫 테스트용 제안값이며 밸런스 검증 전이다.

## 0. 한 문장 게임 정의
**실제 점프·포고·검격·회피를 자유롭게 조작하면서, A/S/D/F 세 개의 결인으로 즉시 인술을 만들고, 이번 판에 선택한 인술 진화와 금술 때문에 같은 레시피라도 전혀 다른 액션을 수행하는 횡스크롤 닌자 액션 로그라이크.**

### 재미의 네 기둥
1. **손 조작**: Z 3타·상향/하향 베기·포고·X 완벽 회피·Space 가변 점프·C 피니시가 인술 없이도 유효하다.
2. **결인 숙련**: 단일키 첫 입력으로 단일기를 쓰고 0.75초 내 3인 조합이 완성되면 **세 번째 입력 즉시** 혼합 인술이 발동한다. V 확정/스킬 기억 슬롯 없음.
3. **빌드 변형**: 획득한 진화가 투사체를 돌진으로, 장판을 점프 발판으로, 폭발을 충전 검격으로 바꾸는 등 **행동 선택을 변화**시킨다.
4. **로그라이크 의사결정**: 무작위 보상/다음 방 위험/금술의 대가/속성별 전투방 대응 때문에 반복 런이 서로 다른다.

## 1. P3부터 반드시 유지할 것
- 장르: **2D side-view platform action**, fixed-step gravity, 벽/천장/일방향 플랫폼/착지와 가변 점프. 가짜 airHeight와 8방향 탑뷰 이동 금지.
- 키: 좌우 방향키 이동, ↑ 상향 공격·조준, ↓ 공중 하향 공격·낙하, Space 점프, Z 공격(홀드 반복), X 대시, C 근접 띄우기/격추, A=화 S=수 D=뇌 F=풍, Enter/Esc 메뉴.
- 첫 인(예 A)에서 `SINGLE_FIRE` **즉시 시전**, 둘째 인은 시전 없음/프리뷰, 셋째 인 완료 시 `NIN_xxx` **즉시 자동 시전**. FFF/WWW/LLL/VVV도 3인 상위 단일 인술 자동 시전. 0.75초 timeout; 홀드 반복 제외.
- 인술 레시피 정확히 20개. 기본 인술 전부 접근 가능하고, 레시피 자체를 레벨업 RNG로 잠그지 않는다.
- 진화 없으면 기존 P3 공격을 그대로 사용해야 한다. P4 데이터가 로드 실패하면 안전하게 기본 스킬로 폴백한다.
- MEAT MARKET 저장 키와 기존 산출물 보존, 별도 P4 세이브 키 사용. 코드상 실제 P3 플레이어 원본/실행 경로가 불명확하면 먼저 감사하고 보고.
- 인술 속성 반응(젖음→감전, 점화→풍, 점화→수, 감전→화 등)은 P3처럼 유지. 반응 1개가 자신을 계속 재발동시키는 무한 고리 금지.

## 2. 런 빌드 슬롯과 선택 제한
| 레이어 | 장착 가능 | 변화 내용 | 교체 |
|---|---:|---|---|
| 검술 유파 | 1 | Z 전체 공격 구조 + 공중·포고 역할 | 보상으로 교체 가능, 현재 유파 리셋 |
| 회피 인법 | 1 | X 뒤 공격/위치/PerfectDodge 활용 | 보상으로 교체 가능 |
| **주력 인술 진화** | 1 | 레시피 20종 중 1개의 A/B 진화 | 최초 확정 후 **그 인술만** 진화; 교체 보상에서는 명시적 재지정 |
| **보조 인술 진화** | 1 | 다른 레시피 1개의 A/B 진화 | 주력과 같은 레시피 중복 금지 |
| 융합 비술 | 1 | 두 원소의 반응/시전 타이밍 변화 | 선택한 비술만 |
| **금술** | 0~1 | 큰 행동 변화와 실질적 페널티 | 취소/교체는 희귀 정화 방에서만 |
| 일반 각인 | 2 | 수치+조건/연계 소폭 조정 | 다른 각인으로 교체 가능 |

- 20개의 인술은 **항상 발동 가능**. 진화는 최대 두 인술에만 적용하여 현재 런의 대표 전투 스타일을 만들도록 설계.
- 기본 인술과 진화는 같은 레시피/키 조합을 쓰며, 플레이어에게 별도 전투 키를 추가하지 않는다.
- 인술 진화는 각 레시피마다 A 또는 B 중 **하나를 선택**. 다른 쪽과 중첩 불가. 현재 런에서 다른 레시피로 갈아타려면 명시적 교체 제안 또는 수행장 보상 필요.
- 융합 비술 1개는 진화 2개와 독립 슬롯. 금술은 **강력하지만 부담 있는 유혹**으로 설계, 유무에 따라 클리어 가능해야 함.
- 빌드는 이름을 장착하는 게 아니라 **상호작용하는 보상들을 획득해 완성**; 아래 12개는 구현 및 밸런스 검증용 목표 빌드이자 가중치 예시. 초반부터 미리 고른 빌드로 강제하지 않음.

## 3. 20개 인술 × 두 갈래 = 40개 액션 진화
**공통 규칙**: 모든 진화는 기본 스킬을 완전히 비활성화하지 않고 판정 구조/이동/설치/조건 중 최소 1개를 교체한다. 이름만 바꾸거나 피해량 +%로 끝내지 않는다. 각 진화엔 typed-operation, 발동 윈도, 지형 검사, maxEntities, 공격 횟수/히트 간격, 보스 대체 효과, 재귀 제한, 조작 피드백을 반드시 부여한다.

**빌드 보상 부여 검증**: 위 표에서 사용한 진화 명칭이 각 레시피 정의의 A/B 중 정확히 한 개에 매핑되는지 프로그램으로 검사한다. 동일 이름을 새 기술 정의로 생성하지 않는다. 각 빌드는 검사 전용 치트 설정 및 통상적인 런 성장 경로 양쪽에서 완성 가능해야 한다.

## 9. 룸/경로 로그라이크 구조 (5~8분 프로토타입 → 12~18분 목표)
### 9.1 룸 종류 (하나의 화면 = 하나의 읽기 쉬운 교전)
- **일반 전투방**: 3~5개의 수제 플랫폼 레이아웃 + 적 구성 난수. 반드시 상·하향 공격과 회피가 의미 있어야 함.
- **정예 전투방**: 위험한 패턴 보상으로 금술/진화 등 희귀 보상 확률을 높임.
- **수행장**: 검술 유파 또는 회피 인법 교체, 현재 인술 진화가 호환되는지 프리뷰.
- **속성 제단**: 인술 진화 A/B를 주력·보조에 한 개 선택. 기존 진화 다른 쪽으로 바꾸려면 선택 비용 필요.
- **금술 제단**: 금술 획득 또는 정화 중 선택, 치료/체력 대가 명확히 표시.
- **상점**: 회복, 리롤, 선택지 보충, 단일 진화 교체 재화.
- **회복방**: 생존, 인술 강화, 리롤 재화 중 하나 선택.
- **보스방**: 거대한 체력만 아니라 포고/대시/성분 상태의 활용 패턴 검증.

### 9.2 경로 선택과 난수
- 1막 시작 후 매 층 **2개 경로 중 선택**, 2~3 방마다 합류. 경로 아이콘/위험도/예상 보상 타입 표시; 숨겨진 결과라도 보상 범주는 보여준다.
- **수제 전투방 12종**(플랫폼 간격/높이/낙하 위험/벽), 적 패키지 8종부터 시작. 무작위 단순 플랫폼 난사 금지(포고·인술 지형 기능을 깨뜨림).
- 초기 5~8분: 5~7개 방+정예 1+보스 1. 이후 12~18분은 3막/20~25방 확장; 숫자는 밸런스 테스트로 조정.
- 한 판의 레시피 사용 가능 기술은 모두 동일하지만, **주력 2개의 진화·융합·금술·방 경로**가 다르게 선택되어야 함.
- 적 속성 저항은 완전 면역 금지; 보스가 한 빌드 전체를 무효화하지 않게 물리 Z/C, 상태 경직 대체를 남긴다.

## 10. 보상 생성과 획득 가능성
### 10.1 선택지 3장 기본 가중치 (합 100, 초기 제안)
| 풀 | 가중치 | 조건 |
|---|---:|---|
| 신규 유파/회피 | 20 | 슬롯이 비었거나 교체 가능 |
| 주력/보조 인술 진화 | 35 | 슬롯 여유 또는 교체 보상 |
| 융합 비술 | 15 | 1개 슬롯 비거나 교체 조건 |
| 일반 각인 | 20 | 최대 2개 |
| 회복·리롤·재화 | 10 | 언제나 유효 |

- 금술은 일반 풀에서 제외하고 특수방에서만 부여. 진화 보상은 해당 인술 레시피를 **다시 입력할 필요 없이** 목록을 보고 선택할 수 있어야 한다.
- 렌더 카드에는 '기존 판정→새 판정', '공중/지상', '마이너스 효과', '시너지 원소', '이미 진화 적용 중'을 분명하게 표시.
- 이미 최대 장착한 동일 보상, 미구현 id, 같은 기술의 A/B 중복, 융합 비술 2개 중복은 풀에서 제외.
- 빌드 보장: 3분 이내 첫 인술 진화, 5분 이내 2개 진화 또는 융합 비술 하나(짧은 프로토타입의 테스트 목표). 강제 드롭은 최소화하되 슬롯 빈칸과 태그를 고려한 가중치 조절.
- **공정성**: 특정 인술 진화만 계속 등장하지 않도록 3번 연속 미선택 태그가 있으면 후보 가중치를 완만하게 보정; 완성 빌드 무조건 보장은 하지 않는다.
- 리롤 2회 기본, 재화 구매/정예 보상 추가 가능.

## 11. 구현 API와 데이터 저장
```ts
type NinjutsuEvolutionDefinition = {
 id:string; baseNinjutsuId:string; branch:'A'|'B';
 operations:TypedOperation[]; replaceOperations:string[];
 movementRules?:MovementRule[]; entityCaps:Record<string,number>;
 requiredState?:string[]; cooldownOverrides?:number;
 tags:string[]; fxId:string; tooltip:string;
};
type SwordStyle = {id:string; comboGraph:TypedActionNode[]; airGraph:TypedActionNode[]; recoveryRules:any};
type DashStyle = {id:string; dashHookOps:TypedOperation[]; perfectDodgeOps:TypedOperation[]};
type FusionSecret = {id:string; trigger:{statusPair:string[];eventType:string}; operations:TypedOperation[]; icd:number};
type ForbiddenArt = {id:string; rewardOps:TypedOperation[]; costs:CostRule[]; restrictions:string[]};
type RunBuildV4 = {
 version:4; swordStyleId:string|null; dashStyleId:string|null;
 ninjutsuEvolutionSlots:[string|null,string|null]; fusionSecretId:string|null;
 forbiddenArtId:string|null; sigilIds:string[]; rerolls:number;
};
```
- 기존 P3 ninjutsu data는 canonical ID 유지: `NIN_001..NIN_020`. 진화 ID는 `EV_01_A..EV_20_B`처럼 별도 참조. 해당 base ID와 조합(FFF 등) 매핑을 데이터 자동 검증한다.
- 진화 수정은 **기존 시전 파이프라인에 typed op modifier**로 적용; 무작정 변형 코드 40개를 복붙하지 않음. 공격 기하/이동/소환체/상태반응에 공통 모듈을 재사용.
- 이벤트 순서: 인 입력 → 링버퍼 3개 검사 → skill ID 확정 → 진화 선택 조회 → 비용·쿨다운 검사 → 시전/공중 상태 확정 → 판정/이펙트 → 속성 반응 → 처치/보상.
- 단일키 기본기는 3인 스킬 입력시 1회만 발생하고 인술 쿨다운과 충돌해 연쇄 기술이 누락되지 않도록 `CastQueue` 1칸 및 취소창 규칙 유지.
- 최초 시전 뒤 단일기에서 상태이상 적용, 이어 혼합기로 반응을 만드는 보상은 의도된 디자인. 첫 단일기를 자동으로 없애지 않는다.
- 본체 인술과 진화가 추가로 뽑은 `secondary` 효과의 중복 분리; 재귀 증식/복제 차단. 동일 히트 인스턴스 동일 대상 중복 적중 기본 금지.
- `CombatEvents` 루트 깊이 최대 4, 이벤트 최대 64, 소환체/영역/발판 최대치. 스킬 시전마다 독립 root/instance ID.
- 지상 장판은 실제 충돌 가능한 플랫폼에서만 생성, 공중 낙하 없는 가짜 발판/상태 불허. 진화 발판은 임시 collision entity이고 착지·벽 충돌을 게임 물리로 처리.
- `RunBuildV4`는 **P3 이전 세이브와 호환**. 별도 storage key `kage-in.build.v4` 사용, 구버전 정보는 문서화한 migration 처리, 알 수 없는 선택 ID는 제거하고 기본 상태로 폴백.
- 프로토타입은 JS ES modules + Canvas+Node 스크립트. `src/physics2d.js`, `src/seals.js`, `src/ninjutsu.js` 등 P3 실제 구현 파일 먼저 확인하고 그 구조에 맞춘다.

## 12. 액션 가독성과 연출
- 각 진화 A/B는 **실루엣부터 다르게**: 돌진=잔상 위치 이동, 장판=지면 파동, 충전=칼날 광량 상승, 분신=지연 궤적, 발판=실제 밟을 수 있는 광륜.
- 화면 흔들림은 최대 4px/0.12초, 공중 포고 적중과 금술 발동은 별도 색/음향/히트스톱 차등. 시인성/광과민성 설정 제공.
- 인술 경고·보스 공격 예고가 파티클에 가려지지 않게 위험 경고 렌더 레이어 최상위.
- P4 새로운 3택 카드에 **기술 사용 전→후 짧은 판정 프리뷰**(지연된 애니메이션 또는 정적 실루엣) 구현. 전투 중 키보드 방향키+Enter 유지.
- HUD: 2개 인술 진화 아이콘 + 현재 융합 + 금술 대가/쿨다운 상태. 빈 슬롯일 땐 숨겨 시야 방해 최소.
- 60fps 목표; 파티클 수와 실제 타격 판정 예산 분리. 성능이 부족하면 FX 수 줄이고 기술 판정은 정확히 유지.

## 14. 필수 테스트/수용 기준
1. 기본 P3 조작/물리/3인 결인/20개 레시피/4개 단일 인술은 진화 미장착 때 동일.
2. **40개 진화 데이터** 모두 유효한 원본 NIN ID·고유 id, A/B 중복 배제. 모든 진화가 수치뿐 아닌 위치·판정·액션 상태의 차이를 실제 기록한다.
3. 진화 두 슬롯은 서로 다른 인술만 장착하며, 한 인술의 A/B 중복 불가. 교체 시 이전 이벤트·임시 개체가 남지 않는다.
4. 검술 4/회피 4/융합 6/금술 8 모두 데이터 정의뿐 아니라 **게임 내부 효과**가 작동하고 UI에 대가 표시.
5. 단일 입력 A에서 FIRE 1회, 0.75초 내 ASD 조합 성공시 FWL 혼합 1회. 인술 진화는 이 인풋 규칙을 수정하지 않음.
6. PerfectDodge 실제 충돌, 공중 포고 실제 충돌, 보스 띄우기 대체, 임시 발판 접촉, 벽 관통 방지.
7. 속성 반응·2차 진화 추가 공격·금술 복제 재귀 무한 루프 없음. Max eventDepth/chainCount 적용.
8. 12개 참조 빌드에 대한 seeded scenario: 해당 스킬만으로 가능한 동작과 실제로 다른 전투 판단 기록. 단순 DPS 차이만이면 불합격.
9. 5~8분 테스트 런 10개 시드에서 진화 최소 1개는 3분 이내, 성격이 다른 성장 2회는 5분 이내 확인(목표; 실패 시 통계 보고).
10. 무작위 방은 수제 충돌 레이아웃 유효성 검사, 일방향 발판 정상, 낙사 트랩 안전한 부활/실패 처리.
11. 기존 저장 파일(없는/낡은/깨진 스키마), 기존 P2 배포 파일, main 게임 코드 보존.
12. 실 브라우저 smoke에서 키보드 3택/보상/검술/결인/진화 스킬/금술 부작용/가시적 FX 검증. `npm test`, `npm run check`, `npm run build:pages`, `npm run build:standalone`이 현재 repo 스크립트와 동작하도록 함.
13. UI와 가독성 테스트: 보스 전조 먼저 표시, 색각 구분, 화면 흔들림과 점멸 off 설정, 키 반복/동시 입력 조합.
14. 누락 기능은 **미구현**으로 명시. 문서 체크박스만 완료 표시하거나 스탯치 변경만으로 진화 구현 완료라고 보고 금지.

## 15. 우선순위/범위 결론
- P3 이전 기능이 실제 코드로 존재하지 않는다면 **P3 동작 기반을 먼저 완성**해야 한다. P4 파일만 추가해 작동한다고 주장하지 말 것.
- '20개 인술 × A/B 진화 40개 + 검술 4 + 회피 4 + 융합 6 + 금술 8 + 12개 참조 빌드 + 수제 방 12종'은 **장기 콘텐츠 목표**. P4 초기 프로토타입은 대표 4진화/2유파/2회피/2금술/4방으로 줄여도 좋지만 누락을 명확히 기록한다.
- 진화가 플레이어의 행동 자체를 바꿔야 재미가 살아난다. **한 런에서 다른 인술 레시피를 사용하더라도 어떤 진화를 골랐느냐에 따라 전혀 다른 공간 전략과 회피/점프 타이밍을 쓰게 만드는 것**이 최종 목표다.
