# KAGE//IN V5 — 통합 게임 개발 사양서 (Codex Implementation Contract)

> 2026-11-02 디자인 스냅샷 · 상태: 설계 확정/제안 구분 · **이 문서가 KAGE//IN P3/P4 기획보다 우선**.
> 현재 main의 MEAT MARKET은 다른 프로토타입이다. **기존 파일, 기존 다운로드, 배포, 저장 데이터 임의 삭제/덮어쓰기 금지**. Codex는 구현 전에 실제 소스·기반 브랜치·배포 가능성을 감사하고, 독립적인 KAGE//IN 실행 진입점을 개발할 것.
> 이 문서는 완료된 게임/이미지 업로드를 주장하지 않는다. 아직 구현하지 않은 기능은 TODO 및 테스트로 관리한다.

## 0. 프로젝트 정의 / 범위
- 가제: **KAGE//IN**. 일본 요괴 닌자 3명 중 하나를 골라 쇼군의 성으로 침입해 쇼군을 쓰러뜨리는 **쿼터뷰/탑다운 빠른 액션 로그라이크**.
- 톤: 통쾌하고 유머러스한 B급 요괴 닌자 활극. 과도한 신화·세계구원·비장한 장문 서사 금지. 짧은 대사, 캐릭터끼리의 감정선, 반복 도전 시 반응 변화.
- 최종 클리어 기준 목표 플레이타임 **약 60분/1런** (초심자 실패런은 더 짧고 숙련 플레이어 편차 가능). **기존 2D 사이드뷰, Z/X/C, A/S/D/F 세 인의 결인/20 레시피/자동 혼합 인술 폐기**.
- 플레이 화면: 고정/완만 추적 isometric 카메라, 조준과 입력에 대한 피드백 명확, 시야 가리는 배경 최소화, 적 공격 전조 명확.
- 게임 시작: Title → (Continue / New Run) → Hero Select → Hub → Route/Room → Boss → Acts → Final boss → Results → Hub. Pause, Options, Gallery, Codex/Help, Credits.
- **V5 작업 목표:** 기본부터 끝까지 실제 플레이 가능한 수직 절편을 가능한 많이 구현. 완성된 시스템/스텁/미구현을 UI와 README에서 정확히 구분. 기존 P4의 '20 인술×2 진화'와 이번 V5의 '12 공격×4 지원=48 합성'을 섞지 말 것.

| Space | 짧은 회피/대시(벽·장애물 통과 불가, 무적 시간과 캔슬 규칙 시각화) |
| 1/2/3/4 | 화/수/뇌/풍 속성 중 하나를 **다음 발동 가능 스킬에 부여할 인퓨전**으로 예약 |

| Enter / 클릭 | 선택/확인 |

- 예약 속성은 HUD에서 표시, 스킬의 명시된 1회 히트 이벤트에 소비. 미소비인 채 룸 이동 시 유지 여부는 설정 데이터로 결정(권장: 룸 내 유지/막간 초기화). Q 고유 정체성을 속성별로 별도 192개 만들지 않는다.
- 플레이어 입력 버퍼, 선입력, 대시 중 시전 가능 여부, 공격속도 상한, 히트스톱은 데이터화. 게임 고정 timestep/프레임 독립 판정.

| ID | 이름 | 종족 | 고유무기 | 핵심 |

- **고로 등 뒤 원통형 대포/포신 금지.** 허용 무기는 카나보. 캐릭터 포즈에서 손목/팔/무기축/어깨 관절을 점검.
- **마스터 아트 기준: 키츠네 확정 초상화의 정돈된 하이엔드 도트/먹선.** 의도 없는 종이 노이즈, 모래처럼 덮인 텍스처, 번쩍이는 모바일 RPG 장신구 금지. 제한된 색상 단계, 형태가 구분되는 큰 명암, 절제된 해칭, 선명한 얼굴.
- 라이벌은 주인공의 적·경쟁자이고 주인공 복장을 복제하지 않는다. 공통 차가운 저채도 조합: 상아/청회/짙은 청록/자주/옅은 금. 시로하의 **첫 짧은 백금발·청회색 눈·치켜든 턱·뺨 발그레한 얼굴은 고정**. 변경 가능은 의상 색/부분 소품만.

### 5.1 기술별 고유 행동 (각 행 S01/S02/S03/S04 순)
- O01: 분신 3기 순차 포위검→본체 5연; 사슬로 모은 뒤 다단히트·광역 마무리; 최대 5회 치환 연참; 결계 내 좌클릭마다 추가 검격.
- O02: 분신 3명 교차참→본체 관통 발도; 적을 일렬로 끌어모아 참수; 이동 경로에 동시 지연 선형 참격; 결계 중심 지연 대형 일섬.
- O03: 분신 3명의 검기 수렴 폭발; 검기 명중 시 묶고 당김; 검기를 따라 이동 후 재입력 회수/추적; 결계 둘레에서 내부로 검기 수렴.
- O04: 다른 위치 분신 3기의 회오리; 끌어당김 회오리+마무리; 세 지점 치환하며 회전 잔상; 체류형 강한 회오리 장판.
- O05: 본체+분신 2명의 고속 난무; 사슬 전방 고정 후 부채꼴 난도질; 최대 5표적을 순간이동 난무; 영역 내 좌클릭 잔향 추가 공격.
- O06: 분신 2기 협공 찌르기; 포획 후 도망 타깃 추적 접근; 세 번 위치 바꿔 찌르기; 결계 내 표시된 적에게 접근 추가타.
- O07: 분신 투척 부채꼴 집중; 단도 적중점 간 사슬; 투척 단도로 순간이동 후 베기; 결계 경계의 단도가 진입 대상을 향해 발사.
- O08: 분신 상처 축적→본체 폭발; 출혈 적 연결해 동시 폭발; 출혈 적 차례로 치환하고 파열; 출혈 지속 연장 및 폭발 시 추가 절단.
- O09: 분신 2기 측면 강타→중앙 본체 강타; 끌어모아 귀왕 강타; 목표 위로 낙하 충격파; 작은 진 내 구속 후 초강력 한 방.
- O10: 서로 다른 세 지점 동시 지진; 사슬 대상 사이 지면을 따라 진동 전파; 출발·도착 지진; 지속 진동 장판 내 공격으로 펄스 가속.
- O11: 본체 콤보에 따라 분신 타격 가속; 끌어당긴 후 연속 후려치기; 치환하면서 콤보 유지; 결계 안 공격속도 상승·이탈 시 사라짐.
- O12: 본체+분신 2기 세 방향 철퇴 투척; 사슬 카나보로 잡아당김; 날아간 철퇴에 치환 후 회수 회전; 결계 내 철퇴 순환 후 귀환.
- 모든 Q 데이터에 start/active/recovery, target method, collision geometry, maxHitsPerTarget, knockback/control, iframe policy, VFX hooks, cancel windows, gauge cost, entity cap을 필수로 둔다.

## 6. 강화 트리: 스킬의 공격 범주/성격 유지 (절대 규칙)
- 공격 O마다 E와 좌클릭의 정체성이 유지되어야 함: 발도술은 끝까지 '발도', 투척술은 끝까지 '투척', 진동술은 끝까지 '지진'. **강화로 근본 공격 분류를 바꾸지 않는다.**
- O별 고유 **3개의 방향성이 선명한 분기**를 제시; 한 런에서는 분기 1개를 잠그고 Tier 1→2→3 순서로 강화. S별 3분기도 동일. Tier1 기본 사용법 강조, Tier2 전투루프 강화, Tier3 클라이맥스 변형. 독립적인 범주 변경 없음.
- O 전체 12×3=36라인, S 전체 4×3=12라인; 총 48개의 분기 라인. Q는 **고유 48개의 기본 동작을 유지**하고 공격 분기 Modifier + 지원 분기 Modifier 를 더한다. 48×9개 기술을 복붙하지 않는다.
- 예 O02 발도 분기:
  - 거합귀: 홀드 한방 → 풀차지 후 다음 차지 빠름 → 강한 전방 관통 극대화.
  - 월광검: 직선 발도 검기 → 적중 시 분기 검기 → 왕복 검기.
  - 무영살: 베며 단거리 이동 → 발도 표식 후 좌클릭 파열 → 재입력 적 표식 추적 발도.
  세 방향 모두 **검집에서 뽑는 발도 절단**을 중핵으로 유지.
- S01: 백귀군단(분신 숫자), 거울그림자(좌클릭/E 반영), 그림자덫(고정 매복).
- S02: 사냥꾼(당기기·그물), 처형인(단일 적 묶고 E 누적), 거미줄(지형 간 연결·망).
- S03: 순간살(대상 배후 진입), 환영술사(미끼 잔상과 교환), 공간술사(위치 지정·경로 균열).
- S04: 요새(방어), 감옥(적 구속), 제단(범위 내 E 추가 발동).
- O01/O03/O04/O05~O12의 3분기는 아래 데이터 구조로 **추가 실명/규칙 설계가 필요한 작업**. 임의로 과거 P4 진화 명칭을 가져오지 않는다. Codex는 O별 분기 3개의 역할과 Tier 1/2/3 정의를 만들어 승인 가능한 JSON/Markdown으로 제안한 뒤 구현.
- Q 기본 스킬은 **같은 Q로 보여야 한다**. 분기와 속성은 부가 메커니즘/탄수/타이밍/기절량/잔상 등 차이를 주되 핵심 실루엣·기동 루트·시전 장소를 무작정 갈아엎지 않는다.
- Q 예시 천영발도: 거합귀×백귀군단=분신이 상대를 묶은 뒤 대발도; 월광검×거울그림자=왕복 검기 복제; 무영살×그림자덫=덫 사이 치환 발도. 모든 조합에서 **분신 협공+발도** 정체성 유지.

## 7. 원소 인퓨전 4종
화=점화/지속 대미지, 수=젖음/감속·연계, 뇌=감전/연쇄, 풍=밀기/범위/기동. 정확한 상태 지속시간/계수는 밸런스 데이터로 이동.
- 한 스킬에 인퓨전 1개, 1회 소모. 타 속성의 상태를 만나면 별도 반응 정의(화+수 증기, 수+뇌 감전 전도 등) 가능; 무한 반응 재귀 금지.
- 무속성 공격 스킬도 기능해야 하며 Q 고유 액션은 원소 유무와 무관하게 알아볼 수 있어야 한다.

## 8. 스탯 강화 트리 (인술 분기와 별도 축)
- HP/방어·회피·공격·치명·공격속도·쿨타임/게이지·상태이상·이동성 등 능력 강화 카드. 모든 캐릭터 공통 기반과 무기별 가중치.
- 권장 분류 5: 생존(최대HP, 피해감소, 회복), 무기(기본타, 공속, 치명), 인술(E/RMB 쿨/위력), 합성(Q 충전·범위·최대대상), 기동(대시 회복·이동·회피성능). **속성 특화**는 별도 보상군으로 가능.
- 단계별 퍼센트 증가에 상한 및 diminishing returns; 동일 항목 과다 스택 방지. 유효 DPS/효과를 UI 비교에 표시; 공격·지원 분기 정체성 유지.
- 스탯 보상은 '선택 없는 자동 레벨업'이 아니라 선택형 방 보상과 결합. 초기 수치는 튜닝 값으로 분리; 게임 진행에 따라 플레이어가 강해졌다고 느껴지되 방어 쌓기로 무적 불가.

## 9. 60분 1런 / 5막 제안 구조
**확정 방향:** 기존 계획에서 막 하나 추가, 클리어 약 1시간. 막별 명칭/세부 보스/방 수는 제작용 제안으로 **미확정** 표시.
| 막 | 플레이 시간 목표 | 환경/주제 | 핵심 체험 |
|---|---|---|---|
| Act 1 성 외곽 | 0~10분 | 성 아래 마을/초입 숲 | 기본 무기 선택, 첫 인술 2슬롯, 라이벌 복선 |
| Act 2 외성 | 10~22분 | 문루/경비소 | 특수 병종, 보상 분기, 첫 보스 |
| Act 3 중정 | 22~35분 | 정원/폐허/요괴 감옥 | 공격/지원 분기 Tier 2, 이벤트·계약 |
| Act 4 내성 | 35~48분 | 회랑/탑/인술 수비대 | 고난도 조합, 빌드 정리, 라이벌 재대결 |
| Act 5 천수각 | 48~60분 | 성 최상층/쇼군 | 최종 스킬·상태 점검, 쇼군 보스, 엔딩 |
- 각 막 = 6~10개 일반/선택 방 + 이벤트/상점/회복 + 막 보스(숫자는 테스트 후 조정). 직선 진행 + 중간 갈림길(2~3) + 짧은 루프. 방 간 문을 명확히 2~3개 선택할 수 있게.
- 맵/전투 밀도는 쿼터뷰 카메라에서 피격 예고와 경로를 가리지 않도록 엄격히 제한. 렌더/콜라이더/내비 데이터 분리. 안전한 소환/스폰 지점.
- 막 전환 시 이동/스킬/보상 상태를 보존, 단 층/방마다 난도·보상·적 태그가 달라진다.

## 11. 적/보스/라이벌 및 캐릭터 스토리
### 11.1 서사
- 공통: 쇼군의 요괴 사냥을 끝내기 위해 성에 침입. 세 플레이어의 엔딩·막간 대사/반응 차별화. **가벼운 장난과 빠른 대사** 중심. 영웅들 간 인연과 재시도 시 짧은 농담.
- 카라스: 임무와 흔적 없는 암살/실전 검술, 시로하의 거창한 도전과 대비.
- 키츠네: 탐욕스러운 쇼군의 금고와 악행을 노리는 영리한 괴도, 네코마타와 서로 훔치는 라이벌 관계.
- 고로: 쇼군에게 싸움을 걸고 요괴를 구하는 호쾌한 괴력, 자신보다 강한 아카도를 두려워하면서도 넘어서는 성장.
- 컷신은 짧고 스킵/다시 보기 지원. 주요 대사마다 인물 초상·표정·이름 태그·효과음, 최초/재방문 대사 분기.

## 12. UI / 타이틀 / 갤러리 — 반드시 플레이 가능한 기능
### 12.1 타이틀 16:9
- 고정된 시안: **왼쪽 윗부분 KAGE//IN 로고, 왼쪽 세로 메뉴(START/CONTINUE/SETTINGS/EXIT 및 GALLERY 추가), 오른쪽 카라스·키츠네·고로**, 거대한 붉은 달과 먼 성/도리이/낙엽.

### 12.2 Gallery 세부 계약

- 탭: **캐릭터 / 라이벌 / 타이틀 & 키아트 / 이벤트 일러스트(추후)**.
- 갤러리 항목: preview thumbnail, title, category, art asset path, unlock condition, acquired_at(optional), lore one line, artist credit(optional), aspect ratio.
- **기본 공개**: 캐릭터 3명 대표 초상, 타이틀 아트 1장(최소 4개). 라이벌 3명은 조우/첫 격파에 따라 개별 해금(설정의 UX 옵션으로 언제든 기본 공개 가능하게). 미해금은 실루엣+획득 힌트, 스포일러 텍스트 노출 금지.
- 선택시 상세 화면: 이미지 가득 보기(종횡비 유지/잘림 금지), 이전/다음, 줌, 배경 어둡게, 정보 보기 토글, Esc 뒤로. 메뉴·보상 상태를 건드리지 않음. 마우스 클릭/휠, 키보드 방향/Enter/Esc 지원.
- **타이틀 대표 이미지도 갤러리에서 직접 열고 확대·전체화면 감상** 가능. 추가 키아트/표정 변형/보스 카드가 생기면 manifest에 한 건 추가만으로 목록 노출.
- 저장: 버전드 단독 key `kage-in.gallery.v1` 또는 Unity PlayerPrefs/JSON save; 보유 이미지 unlock set; 옵션·런 저장과 분리, 리셋/백업 가능, JSON 파손 복구, 없는 asset은 placeholder.
- 이미지 로더: 비동기 preload, thumb 캐시, 이미지 실패 폴백, 최대 해상도/메모리 고려, 검은 화면 방지. 썸네일/풀해상도 별도 에셋 참조 가능.
- 라이벌 등장 연동: emit `rival.encountered` → 해당 갤러리 카드 unlock, `rival.defeated` → 추가 변형 아트/대사 unlock. 결과 UI에서 새 항목 표시; 반복 획득 중복 없음.

### 12.3 기타 UI
- HeroSelect: 3 캐릭터 비교, 무기/공격 예시, 선택 확정.
- HUD: HP, 대시, E/RMB cooldown, Q gauge, 예약 속성(1/2/3/4), 현재 O/S 이름·분기 Tier, 상태이상, 룸/막/현재 시간.
- DoorSelection: 선택 경로별 다음 방 예상 체험/보상/위험, 방향·커서 상호작용. 최소 2종 선택지.
- Pause: Resume, Settings, Controls, Gallery(읽기전용), Quit Run 확인.
- 대화: 이름·초상·서브표정·짧은 메시지, 자동/수동 진행, 스킵, 재시청.
- Options: audio buses (BGM/SFX/VO), 화면·UI scale, screen shake, hit flash, colorblind-friendly symbols, 언어 전환(한국어 기본).

## 14. 코드/데이터 아키텍처 · 플랫폼
- **엔진 의사결정:** 최근 대화에서 Unity를 의도하였음. Unity 기반 KAGE//IN 프로젝트를 새 하위 폴더/브랜치에서 구성할 때는 실제 설치/빌드 체인/에셋 임포트 검증. 기존 저장소는 JS Canvas이므로 어느 경로에서 구현할지 먼저 기술 감사 후 보고; Unity가 불가능하면 기존 게임과 별도 웹 수직 절편을 **명시적 대체 구현**으로 제공하고 Unity 프로젝트라고 거짓 주장 금지.
- 권장 Unity 버전: 팀에서 확인한 지원 LTS 하나로 잠금(엔진 버전 추측 금지). 주요 폴더: `Assets/KageIn/Runtime/{Core,Input,Characters,Combat,Ninjutsu,Fusion,Status,AI,Rooms,Progression,UI,Gallery,Save}`, `Data/ScriptableObjects`, `Art`, `Tests`, `Scenes`.
- **데이터 드리븐:** ID를 통한 CharacterDef/OffenseDef/SupportDef/FusionDef/BranchDef/ElementDef/StatUpgradeDef/RoomDef/EnemyDef/BossDef/RivalDef/GalleryEntry. DB/ScriptableObject 구조 버전/검사 및 타입식 modifier pipeline.
- Damage flow: input → castValidate → animation event → spawn hitbox/projectile → faction collision → damage/status → event bus → gauge/drop/telemetry → render; same hit cannot recursively proc itself.
- Q deterministic lookup `fusion = FusionDatabase[(offenseId,supportId)]`, 48 key 중 누락/중복 금지. Modifier는 순서 고정 (base fusion → O branch → S branch → element → stats → global caps).
- Seeded RNG, 이벤트 로깅, 씬 전환 중 상태 저장, pool manager, fixed step collision, hit registry per attack, maxParticles/Entities, map navigation, save versioning.
- 저장은 `kage-in.*` namespace, MEAT MARKET 저장 키 보존.
- 카메라/연출: 캐릭터 실루엣 보존, 회피 전조 가리지 않음, 적 탄막 과다 억제. 60fps PC 목표이나 실측 없이는 달성 주장 금지.
- 선택형 보상/방/라이벌/갤러리 데이터는 디자이너가 코드 변경 없이 편집 가능해야 함.
- 소리: 기본 BGM(타이틀/막간/보스), 피격/발도/철퇴/속성/Q 고유 사운드, 볼륨 버스, mute 기능.

## 15. 개발 우선순위 (많이 만들되 실제 동작하는 단계로 납품)

3. 새 V5 game entry/README/변경파일 목록/테스트 계획을 먼저 제시. 이미지 에셋 실제 위치 확인.

### Phase 1 '보이는 제품'
- 구동 가능한 타이틀(로고, New Game, Continue 상태, Settings, Gallery) 및 아트 7종을 표시하는 **작동하는 갤러리**. 마우스/키보드 전환, unlock, 줌, 저장, 에러 대체 이미지.

- 3인 무기 기본 공격, O 12종 좌클릭+E, S 4종 RMB, 속성 예약 4종, Q 게이지/48 기본 fusion lookup.

### Phase 3 빌드·방

### Phase 4 5막/보스/서사

## 16. 검수·수용 기준 / Codex 작업 완료 정의
- 빌드가 실제 실행되고 Title에서 Start→HeroSelect→Combat→Reward→NextRoom→Boss→Result→Gallery→Title 흐름을 입력으로 통과.
- 3캐릭터 각 기본 공격 체감/애니메이션/피격 판정이 다르고 **고로 총포/대포 없음**.
- E 12종 장착 가능, S 4종 장착 가능, Q 48종 ID·특성·시각/판정 차이 확인. 장비 조합이 바뀌면 Q가 달라지고 기존 스킬 고유 형식 유지.
- 분기 선택 1종 고정/Tier1→2→3 순서/업그레이드가 고유 공격 분류를 바꾸지 않는지 테스트.
- Q/속성/상태이상 반복 복제에 무한 재귀 없음; 게임 중단/죽음/보스 면역/사거리 밖 안전 처리.
- 5막/각 방 유형별 선택 예고와 실보상 카테고리 대조 테스트, 도달가능 경로와 필수 O/S/Q 획득 가능성 검사.
- Gallery 기본 4장(영웅 3/타이틀 1), 라이벌 조우 해금 3장, 줌/뒤로/미해금/이미지 누락·파손·세이브 재시작 테스트.
- 아트 검수: 6인 원본 동일성/각 아트 승인 상태·키츠네 기준 질감 균일·자세/손/무기 접합 검토. 단순 프롬프트 재생성 결과를 원본과 동일하다고 주장하지 않기.
- Title는 16:9 및 720/1080에서 로고·버튼과 캐릭터 중첩 없이 보이고, 장식이 전조/메뉴를 가리지 않음.
- 신규 기능을 구현했다는 커밋에는 테스트 자동화, 실행법, 변경파일, known limitations, 실제 빌드 아티팩트(가능 시)를 포함.
- 게임 구조/리소스/기술 범위를 임의 변경할 필요가 있으면 결정 로그를 남기고, 사용자의 **확정 디자인을 임의 변경하지 않는다**.
