# MEAT MARKET

## 게임 기획 및 Codex 개발 명세서 v1.1

**문서 목적:** Codex를 이용해 실제 플레이 가능한 2D 액션 서바이버 로그라이크 프로토타입 제작

**개발 원칙:** 기존 프로젝트를 먼저 분석하고, 사용 중인 게임 엔진과 언어를 유지한다. 엔진이 정해지지 않은 빈 프로젝트라면 임의로 구현을 시작하지 말고 먼저 엔진을 확인한다.

---

# 1. 게임 개요

## 1.1 기본 정보

- 게임명: MEAT MARKET (가제)
- 장르: 2D 탑다운 액션 서바이버 로그라이크
- 플랫폼: PC
- 조작: 키보드 전용
- 시점: 탑다운
- 런 목표 시간: 15~20분
- 핵심 콘텐츠: 직접 전투, 대량 몬스터 처치, 신체 이식, 빌드 시너지, 과거 빌드 추적자

## 1.2 한 줄 콘셉트

괴물을 죽이고 신체를 뜯어 자신의 몸에 붙여라. 살아남을수록 강력한 괴물이 되고, 죽으면 자신이 만든 괴물이 다음 사냥터에 남는다.

## 1.3 핵심 게임 경험

**액션:** 직접 공격과 회피로 몬스터 무리를 돌파한다.

**성장:** 괴물의 신체 기관을 이식해 공격 방식과 자동 무기를 변화시킨다.

**시너지:** 기관의 효과가 서로 연쇄 반응을 일으켜 강력한 빌드를 형성한다.

**추적자:** 이전 런에서 사망한 플레이어의 빌드가 다음 런의 적으로 등장한다.

### 중요 설계 원칙

게임의 중심은 추적자가 아니라 액션과 빌드 성장이다.

추적자 없이도 일반 몬스터와 정예 몬스터를 상대하며 빌드를 완성하는 과정이 재미있어야 한다.

# 2. 조작 시스템

## 2.1 키보드 배치

| 입력  | 기능            |
| ----- | --------------- |
| ↑     | 위로 이동       |
| ↓     | 아래로 이동     |
| ←     | 왼쪽 이동       |
| →     | 오른쪽 이동     |
| Z     | 기본 공격       |
| X     | 회피 / 대시     |
| C     | 특수 공격       |
| Enter | UI 선택 및 확인 |
| Esc   | 일시정지 / 취소 |

### 필수 사항

- WASD 이동을 사용하지 않는다.
- 마우스 조준과 마우스 클릭을 요구하지 않는다.
- Q/E/F 스킬 연계 시스템을 사용하지 않는다.
- 기관별 추가 액션 키를 만들지 않는다.
- 자동 기관은 별도 입력 없이 작동한다.
- 모든 필수 UI는 키보드로 조작 가능해야 한다.
- 동시에 이동과 공격, 이동과 회피 입력이 가능해야 한다.
- 키보드 동시 입력 문제를 줄이도록 입력 처리를 설계한다.

## 2.2 이동

- 방향키로 8방향 이동한다.
- 대각선 이동 속도는 정규화한다.
- 이동 입력이 없으면 즉시 정지하는 것을 기본으로 한다.
- 공격 중에도 이동할 수 있지만 무기별 이동 속도 보정이 가능해야 한다.
- 이동과 캐릭터가 바라보는 방향은 별도로 관리한다.

## 2.3 공격 방향

마우스 조작이 없으므로 공격 방향은 자동 보정과 마지막 이동 방향을 조합한다.

기본 규칙:

1. 공격 가능한 적이 공격 보정 범위 안에 있으면 가장 적절한 적을 자동 선택한다.
2. 대상이 없으면 캐릭터가 마지막으로 바라본 방향으로 공격한다.
3. 기본 공격은 무기별로 부채꼴 또는 직선 판정을 사용한다.
4. 공격 도중 캐릭터가 의도치 않게 급회전하지 않도록 방향을 잠시 고정할 수 있다.
5. 보정 각도, 탐색 거리, 방향 고정 시간은 데이터로 조절한다.

자동 보정은 편의 기능이지 완전 자동 공격이 아니다.

플레이어는 적절한 방향으로 이동하고 공격 거리를 맞춰야 한다.

## 2.4 기본 공격 — Z

- Z를 누르면 기본 공격한다.
- Z를 길게 누르면 무기 공격 주기에 따라 연속 공격한다.
- 무기별 공격 속도, 사거리, 공격 범위, 넉백, 경직을 가진다.
- 공격에는 준비, 활성, 회복 구간이 있다.
- 공격 도중 회피로 취소할 수 있는 구간을 별도로 설정한다.
- 적중 시 타격 이펙트와 짧은 히트스톱을 제공한다.

## 2.5 회피 — X

- 방향키와 X를 동시에 누르면 해당 방향으로 회피한다.
- 이동 입력이 없으면 마지막 이동 방향으로 회피한다.
- 회피에는 짧은 무적 구간이 존재한다.
- 회피는 기본 2회 충전 방식으로 시작한다.
- 회피 충전과 회복 시간은 데이터로 설정한다.
- 회피 중 일반적인 공격 입력은 버퍼링할 수 있다.

초기 테스트 값:

- 회피 지속 시간: 0.22초
- 무적 시간: 0.16초
- 회피 충전: 2회
- 충전 회복: 2.5초

위 수치는 임시 값이며 플레이테스트 후 조정한다.

## 2.6 특수 공격 — C

- 장착한 팔 기관에 따라 특수 공격이 달라진다.
- 특수 공격에는 쿨다운을 적용한다.
- 일반 공격보다 강력한 피해 또는 전술적 효과를 가진다.
- 공격 중 이동 가능 여부와 회피 취소 여부는 기관별로 설정한다.
- 별도의 마나 시스템은 초기 프로토타입에서 사용하지 않는다.

# 3. 전투 시스템

## 3.1 전투 방향

뱀서류의 대량 몬스터 전투와 액션 게임의 수동 공격을 결합한다.

일반 몬스터는 다수 등장하며 빠르게 처치할 수 있다.

정예 몬스터와 보스는 명확한 공격 전조와 대응 가능한 패턴을 가진다.

플레이어는 이동, 공격, 회피, 특수 공격을 적절하게 조합해야 한다.

## 3.2 기본 전투 요소

- HP
- 이동 속도
- 기본 공격력
- 공격 속도
- 공격 범위
- 치명타 확률
- 회피 충전
- 넉백
- 경직
- 무적
- 상태이상
- 자동 공격
- 공격 발동 이벤트

## 3.3 상태이상

초기 구현 상태이상:

| 상태 | 효과                     |
| ---- | ------------------------ |
| 출혈 | 지속 피해                |
| 독   | 지속 피해, 중첩 가능     |
| 감전 | 추가 전기 피해 또는 전이 |
| 둔화 | 이동 속도 감소           |
| 기절 | 짧은 행동 불능           |

상태이상은 공통 시스템으로 구현한다.

효과마다 지속 시간, 중첩 제한, 갱신 규칙, 적용 대상, 면역 조건을 데이터로 관리한다.

## 3.4 액션성 유지 규칙

자동 무기만으로 모든 적을 쉽게 처리하지 않도록 설계한다.

- 직접 공격에 적절한 경직과 넉백을 부여한다.
- 일부 기관은 직접 공격 적중 시 강화된다.
- 일부 기관은 정확한 회피 성공 시 발동한다.
- 정예 및 보스의 강력한 공격은 회피 타이밍을 요구한다.
- 자동 공격은 일반 몬스터 처리와 지속 화력을 주로 담당한다.

# 4. 신체 이식 시스템

## 4.1 기본 개념

플레이어는 몬스터를 처치하고 신체 기관을 획득한다.

기관을 장착하면 새로운 공격 능력, 자동 무기 또는 패시브 효과를 얻는다.

기관은 게임 내에서 실제 신체 부위로 표현한다.

## 4.2 장착 슬롯

| 슬롯 | 역할                     |
| ---- | ------------------------ |
| 팔   | 주력 무기 및 특수 공격   |
| 등   | 자동 공격 기관           |
| 심장 | 핵심 패시브              |
| 눈   | 표적 지정 및 조건부 효과 |

각 슬롯에는 기관을 하나씩 장착한다.

초기 프로토타입에서는 중복 장착을 허용하지 않는다.

기관 교체 시 기존 기관의 효과를 제거하고 신규 기관의 효과를 적용한다.

## 4.3 기관 데이터

기관 데이터는 코드에 직접 고정하지 않고 별도 리소스로 정의한다.

필수 필드:

- OrganID
- Name
- SlotType
- Description
- Tags
- BaseStats
- TriggerConditions
- Effects
- Cooldown
- TargetingRule
- VisualID
- AvailableMutations
- AIUsageProfile

## 4.4 프로토타입 기관

### 팔 기관

**톱날 팔**

- 근접 부채꼴 연속 공격
- 적중 시 출혈 누적
- 특수 공격: 전방 넓은 범위의 강력한 회전 베기

**가시 발사 팔**

- 전방으로 가시 투사체 발사
- 특수 공격: 다수의 가시를 한 번에 발사
- 적과 거리를 유지하는 플레이에 적합

### 등 기관

**포식 촉수**

- 가까운 적을 자동 공격
- 체력이 낮은 적에게 추가 피해

**기생 포탑**

- 주기적으로 적을 향해 투사체 발사
- 직접 공격한 적을 우선 표적으로 지정

**회전 칼날**

- 플레이어 주변을 회전하며 접촉 피해
- 근접 몬스터 처리에 유리

### 심장 기관

**굶주린 심장**

- 적 처치 시 짧은 공격 속도 강화

**폭발 심장**

- 일정 횟수의 적 처치 후 주변에 충격파 발생

### 눈 기관

**핏빛 눈**

- 출혈 상태의 적에게 자동 기관의 표적 우선순위 증가

**사냥꾼의 눈**

- 직접 공격한 적에게 짧은 표식 부여
- 표식 대상에 자동 기관의 추가 피해 적용

# 5. 변이 시스템

## 5.1 개요

기관을 장착한 이후에는 변이를 획득해 작동 방식을 변화시킨다.

변이는 단순 수치 강화보다 행동 변화와 시너지를 우선한다.

## 5.2 초기 변이 12종

| ID    | 이름 | 효과                                  |
| ----- | ---- | ------------------------------------- |
| MUT01 | 분열 | 투사체 적중 시 작은 투사체 생성       |
| MUT02 | 관통 | 투사체가 적을 관통                    |
| MUT03 | 폭발 | 조건 충족 시 범위 폭발                |
| MUT04 | 전염 | 상태이상을 주변 적에게 전파           |
| MUT05 | 흡혈 | 지정된 공격으로 피해를 주면 체력 회복 |
| MUT06 | 복제 | 조건 충족 시 마지막 공격 추가 발동    |
| MUT07 | 가속 | 적 처치 후 일시적으로 공격 속도 증가  |
| MUT08 | 반격 | 회피 성공 후 추가 공격                |
| MUT09 | 처형 | 체력이 낮은 적에게 추가 피해          |
| MUT10 | 집중 | 같은 적을 연속 공격하면 피해 증가     |
| MUT11 | 귀환 | 투사체가 돌아오며 추가 타격           |
| MUT12 | 연쇄 | 특정 적중 효과가 주변 대상으로 확산   |

모든 변이를 모든 기관에 무조건 적용하지 않는다.

기관별로 지원 가능한 변이 목록을 설정한다.

## 5.3 변이 데이터

필수 필드:

- MutationID
- Name
- CompatibleTags
- TriggerEvent
- Conditions
- EffectOperations
- InternalCooldown
- MaxTriggerCount
- VisualID

## 5.4 시너지 규칙

기관과 변이는 공통 전투 이벤트를 통해 상호작용한다.

지원 이벤트:

- OnAttack
- OnHit
- OnDirectHit
- OnKill
- OnDash
- OnSuccessfulEvade
- OnStatusApplied
- OnProjectileHit
- OnOrganTriggered

### 예시: 출혈 처형 빌드

1. 톱날 팔로 적에게 출혈을 누적한다.
2. 핏빛 눈이 출혈 대상의 우선순위를 높인다.
3. 포식 촉수가 해당 적을 집중 공격한다.
4. 처형에 성공하면 굶주린 심장이 공격 속도를 높인다.
5. 강화된 기본 공격으로 다음 적을 공격한다.

### 예시: 회피 반격 빌드

1. 플레이어가 적의 공격을 X로 회피한다.
2. 성공적인 회피 판정이 발생한다.
3. 반격 변이가 활성화된다.
4. 주변 적에게 가시가 발사된다.
5. 가시의 적중 효과가 다른 변이와 상호작용한다.

### 중요 구현 규칙

- 효과의 연쇄 발동을 지원한다.
- 동일 이벤트에서 중복 발동을 방지한다.
- 무한 재귀를 방지하는 최대 연쇄 깊이를 설정한다.
- 연쇄 효과에는 출처 ID를 부여한다.
- 필요하면 내부 쿨다운과 발동 횟수 제한을 적용한다.
- 이벤트 처리 순서는 결정적이어야 한다.

# 6. 성장 시스템

## 6.1 경험치

몬스터 처치 시 경험치 오브를 생성한다.

플레이어가 가까이 접근하면 오브를 흡수한다.

일정 경험치에 도달하면 레벨업한다.

## 6.2 레벨업 선택

레벨업 시 게임을 일시정지하고 3개의 보상 후보를 표시한다.

보상 종류:

1. 신규 기관
2. 기존 기관 교체
3. 기관 변이
4. 기존 효과 강화

### 보상 생성 규칙

- 현재 장착 상태를 검사한다.
- 장착 불가능한 기관은 제외한다.
- 호환되지 않는 변이는 제외한다.
- 가능한 경우 현재 빌드와 시너지가 있는 후보를 최소 1개 포함한다.
- 나머지 후보는 새로운 빌드 방향을 선택할 기회를 제공한다.
- 후보가 부족하면 유효한 강화 보상으로 대체한다.

## 6.3 키보드 UI

- 방향키 ↑↓로 후보 이동
- Enter로 선택
- Esc는 허용된 화면에서만 취소
- 레벨업 화면에서는 전투 시간 정지
- 마우스 없이 모든 선택을 완료할 수 있어야 한다.

# 7. 몬스터 시스템

## 7.1 일반 몬스터

초기 4종:

**굶주린 것**

- 근접 추격형
- 낮은 체력
- 다수 등장

**기어오는 것**

- 빠른 이동
- 낮은 피해
- 측면 접근

**침 뱉는 것**

- 원거리 공격
- 일정 거리 유지
- 투사체 전조 제공

**터지는 것**

- 접근 후 자폭
- 사망 시 폭발
- 주변 몬스터에게도 영향을 줄 수 있도록 설정 가능

## 7.2 정예 몬스터

**고기 집게**

- 플레이어를 향해 갈고리 발사
- 적중 시 끌어당김
- 공격 전조 제공
- 갈고리 실패 시 짧은 빈틈 발생

## 7.3 보스

**도축장 주인**

주요 패턴:

- 넓은 범위 베기
- 갈고리 투척
- 직선 돌진
- 바닥 위험 구역 생성

보스 공격은 플레이어가 시각적으로 구분할 수 있어야 한다.

패턴마다 전조, 공격, 회복 구간을 명확하게 구분한다.

# 8. 추적자 시스템

## 8.1 핵심 규칙

플레이어가 사망하면 장착 기관과 변이, 전투 성향을 저장한다.

이 기록을 기반으로 이후 런에서 추적자를 생성한다.

## 8.2 저장 데이터

- DeathID
- RunID
- EquippedOrganIDs
- MutationIDs
- MainAttackProfile
- SpecialAttackProfile
- AutoAttackProfiles
- CombatStatistics
- DeathTime
- DeathCause

## 8.3 추적자 AI

기본 상태:

- Patrol
- Investigate
- Chase
- Attack
- Retreat
- Search

추적자는 저장된 빌드의 핵심 능력을 사용한다.

예시:

- 근접 출혈 빌드: 플레이어에게 접근해 연속 공격
- 원거리 투사체 빌드: 거리를 유지하며 공격
- 회피 반격 빌드: 공격을 피하고 반격

추적자는 플레이어의 위치를 항상 알지 못한다.

시야와 마지막 목격 위치를 기반으로 행동한다.

## 8.4 추적자 보상

처치 시 해당 추적자가 보유한 기관 또는 변이 중 일부를 보상으로 제공한다.

추적자 출현은 매 런 보장하지 않는다.

초기 프로토타입에서는 테스트 목적으로 강제 소환 기능을 제공한다.

# 9. 세계관 및 스토리

## 9.1 기본 설정

세상에는 괴물을 사고파는 거대한 사냥터가 있다.

사람들은 돈을 벌기 위해 그곳에 들어간다.

괴물을 죽이면 신체 부위를 얻을 수 있고, 그 부위를 자신의 몸에 이식하면 강해진다.

하지만 사냥터 안에서 죽은 사냥꾼 역시 상품이 된다.

## 9.2 주인공

빚을 갚기 위해 사냥터에 들어온 신참 사냥꾼.

특별한 혈통이나 숨겨진 초능력은 없다.

목표는 괴물을 죽이고 살아서 탈출하는 것이다.

## 9.3 오프닝

어두운 도축장 입구.

철문 위에 문구가 적혀 있다.

"살아 나오면 전부 당신 겁니다."

철문이 열리고 괴물들이 쏟아져 나온다.

플레이어는 괴물을 처치하고 처음으로 신체 기관을 이식한다.

화면에 짧은 문구가 나타난다.

"상품 가치 상승."

별도의 긴 설명 없이 전투를 이어간다.

## 9.4 스토리 진행

**1막 — 첫 사냥**

신체를 개조하며 사냥터에서 살아남는다.

**2막 — 사냥꾼의 가격**

이전에 죽은 사냥꾼들이 괴물이 되어 등장한다.

**3막 — 최고 상품**

사냥터에서 가장 비싼 상품은 수많은 기관을 이식한 사냥꾼 자신이라는 사실을 알게 된다.

## 9.5 스토리 연출 원칙

- 긴 설명형 대사 최소화
- 복잡한 고유명사 지양
- 환경과 적의 외형으로 상황 전달
- 짧고 강렬한 문구 활용
- 전투 흐름을 방해하는 컷신 최소화

# 12. 기술 설계 요구사항

- 키보드 입력 처리

- 공격 요청

### CombatComponent

- 피해 계산
- 공격 판정

- 공격 상태

- 기관 장착

### MutationSystem

- 변이 등록

### CombatEventSystem

- 이벤트 구독

- 몬스터 상태 관리

### HunterSystem

- 사망 기록 저장

# 13. Codex 개발 단계

## Phase 0 — 프로젝트 분석

구현 전 다음 사항을 확인한다.

- 엔진과 버전
- 프로그래밍 언어
- 기존 프로젝트 구조
- 현재 구현된 기능
- 실행 및 테스트 방법

분석 결과를 바탕으로 개발 계획을 먼저 작성한다.

## Phase 1 — 기본 플레이

구현 범위:

- 방향키 이동
- 8방향 이동
- Z 기본 공격
- X 회피
- C 특수 공격
- 공격 방향 자동 보정
- 플레이어 HP
- 기본 몬스터 1종
- 피격 및 사망 처리

완료 조건:

마우스 없이 플레이어를 이동시키고, 몬스터를 공격하고, 공격을 회피할 수 있어야 한다.

## Phase 2 — 액션 전투

구현 범위:

- 공격 선후딜
- 공격 입력 버퍼
- 회피 취소
- 히트스톱
- 넉백 및 경직
- 기본 몬스터 4종
- 적 공격 전조
- 몬스터 웨이브

완료 조건:

다수의 몬스터와 싸울 때 공격 타이밍과 회피 타이밍이 구분되어야 한다.

## Phase 3 — 신체 이식

구현 범위:

- 기관 슬롯 4종
- 기관 장착 및 교체
- 팔 기관 2종
- 등 기관 3종
- 심장 기관 2종
- 눈 기관 2종
- 자동 공격
- 기관별 외형 표시

완료 조건:

장착 기관에 따라 실제 전투 방식이 달라져야 한다.

## Phase 4 — 변이 및 빌드

구현 범위:

- 변이 데이터 시스템
- 변이 12종
- 공통 전투 이벤트
- 기관 간 시너지
- 연쇄 발동 제한
- 경험치 및 레벨업
- 키보드 보상 선택 UI

완료 조건:

서로 다른 기관과 변이를 조합해 최소 3가지 구분되는 전투 스타일을 만들 수 있어야 한다.

## Phase 5 — 추적자

구현 범위:

- 사망 빌드 저장
- 저장 데이터 불러오기
- 추적자 생성
- 빌드에 따른 AI 행동
- 추적자 보상

완료 조건:

이전 런에서 사용한 기관과 변이의 핵심 효과를 가진 적이 다음 런에 등장해야 한다.

## Phase 6 — 보스 및 런 완성

구현 범위:

- 정예 몬스터
- 도축장 주인 보스
- 런 시작 및 종료
- 시간 기반 난이도 상승
- 사망 결과 화면
- 재시작
- 기본 밸런싱

완료 조건:

하나의 짧은 런을 시작부터 종료까지 정상적으로 플레이할 수 있어야 한다.

# 14. 필수 테스트

## 입력

1. 방향키로 8방향 이동한다.
2. 대각선 이동이 더 빠르지 않다.
3. 이동하면서 Z 공격이 가능하다.
4. 이동하면서 X 회피가 가능하다.
5. C 특수 공격이 정상적으로 발동한다.
6. 마우스 없이 모든 필수 UI를 사용할 수 있다.
7. 방향키와 액션 키를 동시에 눌러도 입력이 누락되지 않는다.

## 전투

8. 공격 방향 자동 보정이 설정 범위 내에서만 작동한다.
9. 공격 범위 밖의 적에게 피해를 주지 않는다.
10. 무적 시간에는 피격 피해를 받지 않는다.
11. 회피 충전이 정상적으로 회복된다.
12. 공격 입력 버퍼가 의도한 시점에만 실행된다.

## 빌드

13. 기관 장착 시 능력이 활성화된다.
14. 기관 교체 시 이전 효과가 제거된다.
15. 변이 조건을 만족하면 효과가 발동한다.
16. 호환되지 않는 변이는 장착되지 않는다.
17. 연쇄 효과가 무한 반복되지 않는다.
18. 레벨업 보상에 선택 가능한 후보만 등장한다.

## 추적자

19. 플레이어 사망 시 빌드가 저장된다.
20. 재시작 후 저장 기록을 불러올 수 있다.
21. 추적자는 저장된 기관을 사용한다.
22. 추적자의 공격은 플레이어가 회피할 수 있다.

# 15. 개발 우선순위 및 범위 제한

처음부터 전체 게임을 완성하려고 하지 않는다.

**최우선 목표: Phase 1~4의 플레이 가능한 프로토타입**

첫 번째 검증에서는 다음 요소가 중요하다.

- 키보드 조작이 편한가?
- 직접 공격이 재미있는가?
- 회피가 전투에서 의미 있는가?
- 기관을 장착하면 확실히 강해지는가?
- 기관과 변이를 조합하는 선택이 재미있는가?
- 자동 무기가 많아져도 액션성이 유지되는가?

추적자는 이 요소들이 검증된 후 구현한다.

# 16. Codex 작업 지침

Codex는 다음 원칙에 따라 작업한다.

1. 기존 프로젝트를 먼저 분석한다.
2. 엔진과 기존 아키텍처에 맞는 구현 계획을 작성한다.
3. 기능을 작은 단위로 구현한다.
4. 데이터와 실행 로직을 분리한다.
5. 기존 기능을 임의로 삭제하지 않는다.
6. 각 단계 완료 시 가능한 테스트를 실행한다.
7. 실제 구현하지 않은 기능을 완료했다고 보고하지 않는다.
8. 플레이 가능한 상태를 유지하면서 확장한다.
9. 임시 아트가 필요하면 단순 도형과 색상으로 대체할 수 있다.
10. 조작 편의성과 전투 피드백을 시각적 완성도보다 우선한다.
